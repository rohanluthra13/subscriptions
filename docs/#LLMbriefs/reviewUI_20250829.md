# Review UI Enhancement Brief

## Current State

The review UI (`/?view=review`) is a functional interface for users to confirm/reject LLM-identified subscriptions. It currently provides:

- **Simple checklist interface** with Yes/No radio buttons for each subscription
- **Text input fields** for user notes on each item
- **Paper-style design** consistent with the notepad UI
- **Real-time markdown file updates** when user saves changes

### Files Involved
- **Frontend**: `templates/review_view.html`
- **Backend**: `main.py` (methods: `render_review_view()`, `handle_review_save()`)
- **Data**: `resources/llm_notes.md` (markdown file with subscription findings)
- **Parser**: `parse_llm_notes()` and `update_llm_notes()` methods in `main.py`

## Current UI Structure

```html
[Paper Container]
  [Form]
    [Subscription Item 1]
      - Name (bold)
      - Yes/No radio buttons
      - Notes text input
    [Subscription Item 2]
      ...
  [/Form]
  [Save Changes] [Back to Dashboard]
[/Paper Container]
```

## Data Flow

1. **Read**: `parse_llm_notes()` extracts subscription data from markdown
2. **Transport**: Data converted to JSON for UI rendering
3. **Display**: HTML form with radio buttons and text inputs
4. **Submit**: Form data sent as `application/x-www-form-urlencoded`
5. **Update**: `update_llm_notes()` writes changes back to markdown

## Improvements Needed

### 1. Visual Enhancements
- Add visual feedback for reviewed vs unreviewed items (e.g., different background color)
- Show progress indicator (e.g., "5 of 31 reviewed")
- Add subtle animations for better UX
- Consider grouping by category if patterns emerge

### 2. Additional Information Display
- Show domain list for each subscription (currently hidden)
- Display LLM's evidence/notes (currently hidden)
- Add expandable sections for more details
- Consider showing estimated cost if available

### 3. Interaction Improvements
- Add "Select All Yes" / "Select All No" buttons for bulk actions
- Add keyboard shortcuts (Tab to navigate, Space to toggle)
- Auto-save draft changes
- Add confirmation before leaving page with unsaved changes

### 4. Filtering/Sorting
- Add search/filter box to find specific subscriptions
- Sort options (alphabetical, by review status, by domain)
- Hide reviewed items option
- Category filters if applicable

### 5. Data Persistence
- Show last modified timestamp for each item
- Track review history if user changes their mind
- Add export functionality (CSV, JSON)

## Technical Considerations

- **Markdown Format**: Must preserve the exact format for LLM compatibility:
  ```markdown
  **Service Name**
  Domains: [domain1.com, domain2.com]
  Notes: LLM evidence here
  
  User Check: [x] Yes | [ ] No
  User Notes: User's notes here
  ```

- **Form Field Naming**: Current pattern uses `check_{index}`, `notes_{index}`, `name_{index}`
- **URL Encoding**: Uses URLSearchParams, not FormData
- **No JavaScript Framework**: Pure HTML/CSS/vanilla JS approach

## Testing Notes

- Test with 30+ subscriptions for performance
- Verify markdown file updates correctly
- Check edge cases (special characters in names, empty notes)
- Ensure form submission works across browsers

## Success Criteria

1. Users can quickly review all subscriptions
2. Clear visual distinction between reviewed/unreviewed
3. Easy to see additional context when needed
4. Smooth, responsive interactions
5. Data integrity maintained in markdown file

## Current Working Example

The form successfully updates entries. For example:
- "Zoho Workplace" marked as [x] Yes with note "this may be expired"
- "Heptabase" marked as [x] Yes with no additional notes

These changes persist correctly in `resources/llm_notes.md`.
